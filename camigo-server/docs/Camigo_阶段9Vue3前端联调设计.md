# Camigo 阶段9 Vue 3 前端联调设计

## 1. 执行范围

阶段9以《修改意见_最终执行版.md》为唯一业务依据，完成 USER、COURIER、ADMIN 三种角色的前后端联调。前端采用 Vue 3、Composition API、TypeScript 和 Element Plus，视图负责页面编排，业务请求与状态收敛到 composable，展示与交互收敛到组件。

## 2. 配送员端

- 位置确认页读取校园地点并提交当前位置；位置更新与路线重算由后端状态机处理。
- 派单邀请卡展示 5 分钟倒计时、路线、路线增量、综合评分，并提供接受和有限原因拒绝操作；提交期间禁用重复操作，超时后自动刷新。邀请时长按用户在阶段11开始后的明确调整执行。
- 任务列表展示订单号、运单号、承运商、取件站、目的地、尺寸、重量、当前状态、路线顺序、预计到达时间和合法操作。
- 路线面板保留 CURRENT 与业务节点的独立业务语义。两者 `location_id` 相同时可合并视觉呈现，但业务节点仍须单独确认，相邻距离按 0 计算。
- 入柜页面只允许选择尺寸兼容的空闲格口；异常页面支持上报和查看处理状态。

## 3. 管理员端

- 包裹列表可按包裹打开派单详情。
- 派单详情展示全部候选人、路线增量、距离/负载/服务/总评分、活动订单数、算法版本、轮次、邀请/接受/拒绝/超时时间、拒绝原因和最终选中依据。
- 历史派单记录中尚未持久化的路线增量和活动订单数显示“历史未记录”，不反向篡改既有数据。
- 异常列表支持查看并执行恢复配送、恢复分拣或确认退回服务站。
- 包裹生成页由管理员选择或随机生成合法字段，并自动进入正式状态日志和派单流程。

## 4. 学生端

- 包裹详情在满足领取条件时展示四位取件码。
- 学生提交取件码后展示持久的成功结果和取件时间；后端同步完成取件码失效、格口释放、取件记录和包裹状态迁移。

## 5. 删除的旧界面语义

- 不再展示配送优先级。
- 不再展示订单级预计配送时长；预计信息只使用当前路线计算得到的 ETA。
- 删除旧接单入口及预约入口。
- 页面标题移除无业务价值的英文眉题字段。

## 6. API 契约

- `GET /api/delivery-orders/tasks`：返回配送员任务完整事实，不返回旧优先级或订单级预计时长。
- `GET /api/delivery-assignments/current`：返回当前有效派单邀请。
- `POST /api/delivery-assignments/{id}/accept`：接受邀请并生成新路线版本。
- `POST /api/delivery-assignments/{id}/reject`：使用受限拒绝原因拒绝邀请。
- `GET /api/delivery-assignments/parcels/{parcelId}`：按包裹读取完整派单审计记录。
- 阶段5至阶段8已实现的位置、路线、入柜、异常、管理员生成和学生取件接口直接由阶段9页面组合使用。

## 7. 验证

- Vue TypeScript 检查与 Vite 生产构建通过。
- 后端 131 项测试全部通过，包括真实 MySQL 下的配送任务字段和派单审计契约。
- 阶段9界面静态扫描未发现优先级、订单级预计时长、旧接单接口或预约入口。
- 测试前后核心业务表行数一致；数据库测试使用事务回滚，未清理现有数据。
